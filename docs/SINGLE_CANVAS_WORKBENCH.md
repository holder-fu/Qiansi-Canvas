# Bridge 多项目工作台契约

> 历史说明：本文件名为 `SINGLE_CANVAS_WORKBENCH.md`，但自 2026-08-19 起，原“产品只能有一个画布”的契约已经废止。保留文件名是为了让旧链接继续有效；本文是当前多项目产品的工作台契约。

本文定义 Qiansi-Canvas 的项目中心、项目切换、自动保存、Bridge、局域网访问、回收站、素材库与旧数据兼容边界。修改这些模块前必须同时核对 `docs/BRIDGE_PERSISTENCE_V3.md`。

## 产品边界

- 首页提供独立“项目”页面，展示 Bridge 权威项目目录；支持新建、打开、重命名、修改 16:9 封面、创建副本、移动到文件夹和可恢复归档。
- `main-canvas` 是首次安装自动创建的默认项目，始终保留且不可归档；它不再是唯一可见项目。
- `script`、`views`、`video`、`audio` 是每个项目内部的工作台，不是四个独立项目。
- 项目文件夹只整理目录关系。删除文件夹会把其中项目移动到“未分类”，不会删除项目。
- 项目归档不删除全局素材库原文件；项目副本复用稳定受管媒体引用，不复制大文件。

## Bridge 权威

```text
任意本机窗口 / 可信 LAN 终端
             │
             ▼
GET /projects
  version: 2
  catalogRevision
  primaryProjectId: main-canvas
  projects[] / folders[]
             │
             ▼
data/projects/<projectId>/
  project.json
  revisions/<revision>/workspaces/*.json
  revisions/<revision>/trash.json

data/project-archive/
  <archived project>
  .tombstones/<projectId>.json
```

- Bridge 项目目录与项目内容是唯一永久权威。浏览器不得以旧 `localStorage` 项目快照覆盖 Bridge。
- 项目目录写入使用 `catalogRevision` CAS 和跨进程目录锁；项目内容与元数据写入使用 `expectedRevision` CAS 和项目锁。
- 创建请求可携带 `requestId`，重复提交必须返回同一结果，不能创建重复项目或文件夹。
- 新项目由 Bridge 原子创建为空 `views` 工作台，创建并回读成功后才允许打开。
- 项目复制必须在服务端锁内读取来源项目的最新修订，写入新的项目 ID，并校正 manifest/workspace 的项目身份。
- 项目归档先写持久 tombstone，再把项目移动到归档目录；任何迟到保存都必须被 tombstone 拒绝，不能复活已归档项目。
- 封面只接受当前 Bridge 已验证存在的受管 asset 或 media-preview 引用，不能持久化 `blob:`、`data:`、主机文件路径或第三方 URL。

## 安全项目切换事务

项目打开必须按以下顺序执行，任何一步失败都留在来源项目：

1. 记录来源项目、工作台和内容签名，并使更早的切换请求失效。
2. 若当前在画布内，先把来源工作台放入项目快照，再等待 Bridge 保存完成；冲突或失败时停止切换。
3. 读取最新项目完整快照和项目目录，校验 projectId、版本、工作台、修订和 manifest 身份。
4. 目录项目 revision 与完整项目 revision 必须一致；短暂提交窗口可有限重读，不一致时不能拼接两份状态。
5. 读取期间如果来源项目被编辑、激活项目变化或另一个切换已经开始，丢弃迟到响应。
6. 全部校验通过后，一次性替换工作台、节点、连线、页签、回收站、项目素材引用、生成参数和标签；清空跨项目撤销栈与节点选中态。
7. 记录目标项目已观察修订，再把该项目 ID 保存为当前终端的轻量导航偏好。

进入首页也必须先确认当前画布保存成功。归档当前活动项目必须再次确认保存，然后在同一操作中选择并完整载入 `main-canvas` 或其他后继项目；不得留下可继续编辑的已归档内存画布。

## 浏览器与局域网边界

- 浏览器只允许持久化当前终端最后打开的项目 ID、语言、主题、布局、快捷键等轻量偏好；节点、连线、工作台、回收站与媒体仍由 Bridge 持久化。
- 当前项目选择是终端本地偏好，不是共享项目字段。一个 LAN 终端切换项目不能强迫其他终端跟随。
- LAN 观察按当前活动项目建立独立基线；切换项目后必须重置基线，不能把来源项目的 revision 或冲突状态带到目标项目。
- 可信 LAN 可使用项目目录、项目创建/修改与受管媒体；项目归档和文件夹删除保留主机权限，避免远端进行高影响删除。
- 受管媒体保存为主机无关相对地址，并按当前 Bridge base 解析；不同主机名、端口或开发代理前缀不得制造第二份项目内容。

## 旧数据处理

- 已存在的 `main-canvas` 原样成为默认项目，不迁移、不清空、不覆盖。
- Bridge v1 目录会原位升级为 v2 目录；已有合法项目保留并进入项目中心，归档 tombstone 对应的项目不重新暴露。
- Bridge 读取并验证成功前，不清理任何旧浏览器画布数据。
- 旧浏览器节点、连线和回收站不再是生产写入权威；旧项目选择键现在作为轻量“最后打开项目”偏好保留。
- 缺少可靠跨标签 CAS 的旧 IndexedDB 回收站记录不自动删除。
- `data/asset-library/` 是全局素材库，任何项目归档、文件夹删除或项目切换都不能顺带删除其原件。

## 并发与错误

- 完全相同的过期重复写可作为幂等成功返回当前修订；内容不同的过期写必须冲突或经过严格三方无重叠合并。
- 两个 Bridge 进程共享数据目录时，目录与项目事务必须取得跨进程文件锁；锁超时失败关闭，不降级为最后写入覆盖。
- 项目卡片操作同时携带项目 revision 与目录 catalogRevision；冲突后先刷新目录，再允许用户重试。
- 创建、复制或元数据提交与目录更新之间发生中断时，Bridge 下次读取必须依据项目 manifest/pending 记录完成对账，不能永久留下不可见项目或已推进但不可发现的修订。
- 错误提示必须指出是目录冲突、项目修订冲突、读取失败还是本地编辑竞态，不能把所有问题伪装成“其他窗口更新”。
- 冲突项目在用户主动备份并载入主机版本前不能盲目覆盖。

## 必须保留的回归测试

1. 空数据目录只创建一个空 `main-canvas`；随后可新建第二个项目而不改变默认项目内容。
2. 旧 v1/v2 目录中的合法项目全部保留；损坏目录失败关闭且原字节不被覆盖。
3. 创建和文件夹创建的同一 `requestId` 重试不产生重复项。
4. 项目切换始终先保存来源，再完整读取目标；保存冲突、迟到读取或读取期间编辑都不得切换或混合数据。
5. 目录与完整项目必须来自同一 revision；新项目不能继承来源项目的生成参数。
6. 项目元数据、工作台、回收站和目录分别执行正确的 CAS；不同项目的修订不能串用。
7. 服务端副本克隆最新修订、生成新身份并保留节点顺序和稳定媒体引用。
8. 归档写入持久 tombstone；重启、第二 Bridge 进程和迟到 PUT 都不能复活项目。
9. `main-canvas` 归档请求始终拒绝；删除文件夹只清空项目 `folderId`。
10. 项目封面只接受真实存在的 Bridge 受管图片；LAN 和开发代理下仍可显示。
11. 项目中心包含新建、打开、重命名、修改封面、创建副本、移动文件夹和删除确认；默认项目不显示可执行删除。
12. LAN 切换项目会重置观察基线，不会把来源项目内容或冲突提示应用到目标项目。
13. 默认画布背景仍为 `#141414`、`#383838` 点阵、16 px 间距和 1.5 px 点大小。
