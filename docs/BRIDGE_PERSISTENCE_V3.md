# Bridge 单一持久化权威契约

本文定义项目目录、画布工作台、回收站和媒体由本机 Bridge 统一持久化后的唯一契约。多项目目录、切换事务、复制和归档规则以历史路径 `docs/SINGLE_CANVAS_WORKBENCH.md` 中的当前“Bridge 多项目工作台契约”为准。修改上传、自动保存、项目/工作台切换、LAN 协作、生成结果、复制节点、导演台、素材清理或 AI 参考图之前，必须同时核对两份契约与对应回归测试。

## 目标与非目标

### 目标

- Bridge 是项目数据和媒体原件的唯一永久存储权威。
- 浏览器只长期保存当前项目 ID、界面偏好和不含作品内容的轻量配置。
- 画布节点、连线、工作台、回收站、生成结果、原始媒体和缩略图不再新增到 `localStorage` 或 IndexedDB。
- Bridge 未连接时明确进入临时会话或只读状态，不把内存数据描述为“已保存”。
- 旧浏览器数据逐条迁移；只有 Bridge 回读校验和项目修订提交都成功后，才删除旧记录。
- 画布显示可以使用预览图，但 AI、编辑器和可移植导出必须解析原图。

### 非目标

- 本架构消除的是浏览器 `localStorage` / IndexedDB 配额问题，不会消除主机磁盘已满、目录无写权限、Bridge 断线或网络中断。
- 本架构不会依赖扩大浏览器配额，也不会把 Base64 转移到另一个浏览器数据库后继续当永久方案。
- LAN 终端不会把作品永久写入自己的浏览器；它们通过当前可信直连或已配对的 Bridge 写入主机数据目录。

## 数据所有权

```text
Browser UI
  ├─ memory: 当前工作台、撤销栈、临时 blob URL、未提交编辑
  ├─ preferences: 当前项目 ID、语言、主题、布局等轻量偏好
  └─ Bridge API
       ├─ projects/<projectId>: 项目目录与修订
       ├─ workspaces/<workspaceId>: script / views / video / audio
       ├─ trash: 项目回收站元数据
       └─ asset-library: 原文件、预览、索引与引用信息
```

浏览器存储不得成为 Bridge 数据的第二个可写副本。旧 `localStorage` / IndexedDB 只能在兼容迁移期间被读取，迁移完成后不得继续写入。

## 物理文件与稳定地址

1. 用户原文件名只作为显示元数据，不能直接作为磁盘文件名。
2. Bridge 为每次新内容分配不可碰撞的 `assetId`；同名上传绝不覆盖。
3. 物理文件可使用 UUID 或内容哈希加扩展名。对已有 `assetId` 的覆盖必须拒绝，编辑副本必须产生新素材身份。
4. 日期目录不是正确性的必要条件。若未来按日期或哈希前缀分片，只允许作为 Bridge 内部磁盘布局，不能进入节点身份或公开 URL 契约。
5. 节点只保存 Bridge 返回的稳定相对地址，例如 `/asset-library/files/<assetId>`。不能保存宿主绝对路径、上传临时文件名、`127.0.0.1` 绝对地址、Base64 或 `blob:` URL。
6. LAN 客户端收到相同相对地址，并相对当前访问的 Bridge 解析；因此主机地址或端口变化不会改写项目 JSON。

### 开发代理与旧绝对地址兼容

- 开发页面使用 `/__qiansi_bridge` 作为同源代理 base；它是当前运行入口的一部分，不是项目数据的一部分。`/asset-library/files/...`、`/media-preview/files/...` 和 `/output/...` 才是受管媒体的规范根路径。
- 旧快照可能包含 `http://localhost:2895/__qiansi_bridge/...`。读取时先把旧 origin、当前 base 以及重复代理前缀剥离为规范根路径，再相对当前 Bridge base 解析，所以本机直连、LAN 直连与 Vite 代理都只会得到一个正确前缀。
- 工作台、`manifest.assets` 和 LAN 协作轮询的完整项目快照都必须经过相同的地址本地化；提交前则反向便携化为根相对地址。任何实现都不得通过简单的 `bridgeBase + savedPathname` 拼接旧绝对 URL，否则会生成 `/__qiansi_bridge/__qiansi_bridge/...` 并被 LAN 代理按前缀碰撞拒绝。
- 第三方 URL 不参与该规范化。兼容读取也不是历史数据批量迁移；现有修订和媒体文件保持原样，只有正常的后续项目提交继续遵守相对地址契约。

## 素材身份、引用身份与显示地址

| 字段 | 语义 | 是否可以共享 | AI 使用规则 |
| --- | --- | --- | --- |
| `assetId` / `bridgeAssetId` | Bridge 原文件身份 | 复制节点可以共享 | 先解析并验证原件 |
| `referenceId` | 节点或语义槽身份 | 不共享 | 保持角色和顺序 |
| `originalUrl` | 原件稳定地址 | 可以共享 | 核心参考图唯一允许来源 |
| `previewUrl` | 轻量显示预览 | 可以共享 | 禁止作为人物、场景或导演台核心参考 |
| `blob:` | 当前页面临时对象地址 | 仅会话内 | 禁止持久化和提交 |
| `data:` | 旧数据或尚未迁移的输入 | 仅迁移期间 | 未迁移完成不得提交项目 |

相同原图可以同时承担人物 A、人物 B、场景或风格等不同语义角色。不得用 URL 或 `assetId` 对导演台语义槽去重；角色顺序必须由独立 `referenceId`、标签和数组索引保持。

## 上传事务

```text
捕获 projectId + workspaceId + nodeId + source revision
  → Bridge 接收临时文件
  → 校验 MIME、签名、大小、图片尺寸或媒体元数据
  → 生成唯一 assetId 与最终文件名
  → fsync 临时文件
  → 原子 rename 到最终位置
  → 生成独立 preview
  → 回读原件并校验 size/hash
  → 原子更新素材索引
  → 返回 assetId/originalUrl/previewUrl
  → 客户端再次核对捕获的节点身份和 source revision
  → 原子替换节点媒体字段并提交工作台修订
```

任一步失败都不能把节点标记为永久保存。Bridge 未启动时，上传文件只能保留为当前页面的临时 `blob:` URL，并显示“仅本次会话”；刷新前应允许重试或导出原文件。

## 项目与工作台写入

- 项目目录、每个工作台和回收站分别按需读取，不在启动时加载全部项目作品。
- 每个写请求带 `expectedRevision`。当该修订仍在保留窗口内时，Bridge 以它为基线在项目锁内做三方合并：按稳定 `id` 合并节点、边、素材和回收站条目，仅在 JSON 叶子无重叠修改时返回 `rebased: true` 及完整合并项目。同一叶子被双写、删除/重排冲突或基线已被裁剪时仍返回 `409`，绝不改成最后写入者覆盖。
- 客户端观察到的项目修订只能单调递增；迟到的工作台、回收站或 LAN 读取不得把已知修订倒退。细粒度写入发生 rebase 后，只有在完整合并项目仍可安全应用时才能推进本地修订。
- JSON 采用同目录临时文件、flush/fsync 和原子替换；不得直接覆盖唯一正式文件。
- 项目目录提交和工作台提交必须有明确顺序或事务清单。进程在中间退出后，下一次启动能够判定哪一份修订已完成，不能猜测“最后写入者获胜”。
- 自动保存只有收到 Bridge 成功响应和新修订后才显示“已保存”。超时或网络断开属于状态未知，必须查询修订，不能直接用新请求重复覆盖。
- LAN 终端与本机 UI 使用同一修订协议。主机数据是权威，但首次发现双方旧数据分歧时必须保留两份并要求明确选择。

## AI 原图门禁

1. 请求构建先冻结有序引用清单，再解析 `assetId` 或 `originalUrl`。
2. `/media-preview/`、preview 查询地址、缩略图字段、`blob:`、Base64 和旧 IndexedDB URI 不得进入核心参考图数组。
3. 原件缺失或 Bridge 无法读取时，在产生付费请求前停止，不能静默回退缩略图。
4. 显式视频海报兼容是独立字段，只能用于模型定义的海报回退，不能混入人物或场景引用。
5. 迁移和地址规范化不得排序或按 URL 去重 2D/3D 导演台的语义包。

## 旧数据迁移

迁移必须是可中断、幂等、先验证后删除的事务：

1. 只读扫描旧画布根键、项目/工作台分片、资产目录、回收站与所有已知 IndexedDB 媒体库。
2. 对每个媒体 Blob 或 Base64 计算校验值并写入 Bridge；回读验证后记录 `old reference → assetId/originalUrl/previewUrl`。
3. 在内存中重写一个完整工作台快照，确保没有 Base64、`blob:` 或 IndexedDB 稳定 URI。
4. 以 `expectedRevision` 提交工作台和项目目录，再从 Bridge 读取并比较关键字段和修订。
5. 只有上述步骤全部成功，才删除本条旧媒体和对应旧快照；批量迁移中某一项失败不得删除其他仍依赖的数据。
6. 迁移过程中用户继续编辑时，只能对仍等于旧 source revision 的节点做 CAS 替换，不能用迁移前快照覆盖新编辑。
7. LAN 终端旧数据只能由持有该数据的浏览器迁移到当前可信直连或已配对的主机；主机不能假定远端浏览器数据库为空。
8. 迁移完成标志必须保存在 Bridge 的项目迁移元数据中，不能只存在会被清理的浏览器标志。

## 清理与容量管理

迁移后容量管理从浏览器配额转为主机磁盘管理：

- 显示数据目录总占用、各项目占用、素材库占用和可用磁盘空间。
- 清理前扫描所有项目工作台、回收站、生成请求终态和资料库引用。
- 只删除引用数为零且超过保留期的孤立文件；扫描不完整时 fail closed。
- 删除一个复制节点不能删除仍被其他节点、项目或导演台语义槽引用的共享原件。
- 失败上传的临时文件、过期 preview 和已完成生成的孤立输出使用 TTL 清理；正式素材不按日期目录直接批量删除。

## 诚实状态

| 状态 | UI 行为 | 是否允许关闭页面后恢复 |
| --- | --- | --- |
| `saved` | 显示已保存修订 | 是 |
| `saving` | 禁止重复提交同一修订 | 未确认 |
| `session-only` | 明示 Bridge 不可用，可继续临时编辑 | 否 |
| `read-only` | 保留已加载内容，阻止产生无法保存的新永久操作 | 已加载内容可读 |
| `conflict` | 保留双方版本并提供选择/导出 | 是 |
| `migration-required` | 旧数据仍在，允许重试，不删除 | 依赖旧浏览器数据 |
| `disk-full` | 停止写入，提示释放主机磁盘 | 已提交修订可恢复 |

## 必须保留的回归测试

1. 两个同名文件连续上传得到不同 `assetId`，第一个原件内容不变。
2. Bridge 写临时文件后崩溃不会损坏现有项目 JSON；重启可清理或恢复临时事务。
3. 过期 `expectedRevision` 的独立叶子修改能够三方合并；同一叶子双写仍返回冲突，且不能覆盖较新工作台。
4. 本机和 LAN 客户端保存相同相对 URL，并分别解析到当前 Bridge。
5. Bridge 离线上传只生成会话态，刷新前 UI 明确提示未永久保存。
6. 旧 Base64/IndexedDB 数据迁移后 Bridge 回读 hash 一致，项目提交成功后才删除旧记录。
7. 迁移上传成功但项目提交失败时，旧浏览器数据仍完整且可以重试。
8. 复制节点共享底层 `assetId`，但人物 A/B、场景、风格引用身份和顺序不变。
9. UI 使用 preview，真实 AI 请求只收到 original；preview-only 时请求在付费前失败。
10. 2D/3D 导演台相同 URL 的两个语义槽仍发送两项且标签不漂移。
11. 浏览器新会话不产生画布、媒体、回收站或生成结果的 IndexedDB/localStorage 写入。
12. 修订 N 的迟到 GET 不能把已保存的 N+1 倒退；下一次 PUT 必须仍以 N+1 为基线。
13. 细粒度工作台或回收站 rebase 后，完整项目中的其他工作台、素材和回收站不能被旧内存快照回写。
14. Vite HMR 后只保留一组自动保存订阅、启动任务和页面生命周期监听；旧模块队列不得再写 Bridge。
15. 旧 `localhost:2895/__qiansi_bridge/...` 受管地址在当前本机或 LAN 入口规范成一个代理前缀；工作台与 `manifest.assets` 行为一致，第三方 URL 不变。
16. 旧迁移代码可以读取历史数据库，但迁移完成后生产路径不会再次写回。
17. 主机磁盘满、无权限、Bridge 断线、响应超时分别进入明确错误状态，不显示假“已保存”。
18. 项目切换和延迟上传使用冻结的 project/workspace/node/source 身份，不把项目 A 的 URL 回填项目 B。
19. 删除一个节点或项目时，仍被其他工作台或项目引用的素材不会被清理。
